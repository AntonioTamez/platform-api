<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Host network ← container port | Host port 8080 forwards to the container; the API surface is exposed to localhost |
| Container process ← compose env | Environment variables injected by compose into the running process |
| Docker health daemon ← container | Healthcheck command executes inside the container with the container user's privileges |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-05 | Information Disclosure | Exposed port + Development environment | accept | `ASPNETCORE_ENVIRONMENT=Development` (D-08) enables Scalar UI and detailed error pages; acceptable because compose is local-dev only and binds host 8080 (localhost). Production (Cloud Run, Phase 7) does not use this compose file |
| T-06-06 | Information Disclosure | Environment variables in compose | accept | Only `ASPNETCORE_ENVIRONMENT` and `ASPNETCORE_HTTP_PORTS` are set — both non-sensitive; no secrets, connection strings, or keys (EF InMemory needs none) |
| T-06-07 | Denial of Service | Healthcheck probing /health | accept | Healthcheck runs `curl` against the local `/health` endpoint every 30s; negligible load, anonymous endpoint by design (Cloud Run liveness probe) |
| T-06-08 | Spoofing | Service binds 0.0.0.0:8080 in container | accept | Kestrel binds all interfaces inside the container (standard); host exposure is limited to the `"8080:8080"` mapping on localhost, no `0.0.0.0` host binding configured |
</threat_model>
