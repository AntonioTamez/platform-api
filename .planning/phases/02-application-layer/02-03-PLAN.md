<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Mediator dispatcher → ValidationBehavior → Handler | Every command and query passes through this pipeline. Pipeline bypass would mean unvalidated data reaching the handler. |
| FluentValidation validator → ValidationContext<TMessage> | Validators read the message fields. A malformed validator (e.g., reading the wrong property) could silently approve bad input. |
| DI container → AddApplication() | The composition root is where Application services become discoverable by the host. Misregistration here leaves the pipeline behavior dormant. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-09 | Elevation of Privilege | Pipeline bypass — handler runs without validation | mitigate | ValidationBehavior is registered as `IPipelineBehavior<,>` open generic AND will be added to Mediator's PipelineBehaviors list by Phase 4. Mediator's source-generated dispatcher invokes registered behaviors deterministically; there is no public route that calls a handler outside of Mediator.Send. |
| T-02-10 | Tampering | Custom ValidationException masking failure shape | mitigate | RESEARCH.md Anti-Pattern: ValidationBehavior throws `FluentValidation.ValidationException` (the library type carrying the Failures collection), not a custom application exception. Phase 4 will catch this exact type to build RFC 9457 Problem Details (ERR-01, ERR-02). |
| T-02-11 | Denial of Service | Pathological validator (slow rule) blocking all requests | accept | Validators in this phase are simple synchronous rules over four fields. Risk is theoretical; mitigation is to keep validators trivial and rely on FluentValidation's standard async dispatch. |
| T-02-12 | Information Disclosure | ValidationException leaks internal field paths | accept | Validation messages name only the fields the caller supplied (FirstName, DateOfBirth, etc.). Phase 4 wraps the failure into Problem Details — no internal type names or stack traces are exposed to clients. |
| T-02-SC | Tampering | NuGet supply chain | accept | Same disposition as Plans 02-01 and 02-02 — no new packages added; FluentValidation and Mediator.Abstractions remain the only Application dependencies. |
</threat_model>
