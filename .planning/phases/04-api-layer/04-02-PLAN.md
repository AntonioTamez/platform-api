<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP client -> PersonsController | Untrusted JSON bodies and route ints arrive here; the controller delegates content validation to the Mediator pipeline. |
| Exception handler chain -> HTTP response | A bug in a handler could leak internal exception data; mitigated by hard-coded ProblemDetails shapes. |
| JsonPatchDocument application -> UpdatePersonDto | A malicious patch could attempt to set non-existent properties; UpdatePersonDto exposes only four safe-to-modify nullable fields per RESEARCH §Security Domain. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-02-01 | Information Disclosure | ValidationExceptionHandler / PersonNotFoundExceptionHandler | mitigate | Both handlers emit only hard-coded ProblemDetails fields (Type, Title, Status, Detail, Extensions["errors"]); no stack trace, exception type, or inner message leaks beyond the formatted Message string defined on PersonNotFoundException. ASVS V7. |
| T-04-02-02 | Tampering | JsonPatch on UpdatePersonDto | mitigate | Patch target is UpdatePersonDto (POCO with exactly four nullable patchable fields) — NOT the Person domain entity (RESEARCH §Security Domain). PatchPersonHandler then enforces invariants via Person.UpdateName / Person.UpdateDateOfBirth which throw DomainException on invalid input. |
| T-04-02-03 | Denial of Service | JsonPatch document amplification (copy/move ops) | accept | Out of scope for v1 learning project; Microsoft guidance notes optional per-operation count limit. No real database, single-process InMemory store; impact is bounded. Documented in RESEARCH §Known Threat Patterns. |
| T-04-02-04 | Input Validation Bypass (Tampering) | Mediator pipeline | mitigate | ValidationBehavior registered via AddMediator options.PipelineBehaviors in Plan 01 ensures FluentValidation runs before every handler; if a malformed command somehow bypasses ValidationBehavior, Person.Create / Person.UpdateName throw DomainException as a second line of defense. ASVS V5. |
</threat_model>
