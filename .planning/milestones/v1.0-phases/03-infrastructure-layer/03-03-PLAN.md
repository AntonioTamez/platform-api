## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Test → Repository under test | Tests instantiate `new PersonRepository(context)` directly, bypassing DI. This is the correct test boundary — the repository is the unit under test. |
| Test → InMemory store | Each test owns its own InMemory database (Guid-named) — no shared state across the trust boundary between tests. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-10 | Tampering | Cross-test state contamination | mitigate | Every `CreateContext()` call uses `Guid.NewGuid().ToString()` as the InMemory database name (T-02 per RESEARCH.md Pitfall 3). No `IClassFixture` shared context. Acceptance criterion enforces the Guid pattern. |
| T-03-11 | Repudiation | Test passes hide repository bugs | mitigate | One test per IPersonRepository method (T-01). Tests use domain factory `Person.Create` (not raw construction) so domain invariants are part of the round-trip. Mutation tests assert via re-query from the same context — proves SaveChangesAsync was actually called. |
| T-03-12 | Tampering | Test depends on `IQueryable` leak | mitigate | Tests assert on `IReadOnlyList<Person>` shape returned by `GetAllAsync`. If a future refactor changes the signature to `IQueryable`, the assertion `result[0].FirstName` still compiles, but Plan 01 acceptance criterion (no `IQueryable<Person>` in repository source) blocks the regression upstream. |
| T-03-SC | Tampering | Test-project package installs | mitigate | All five packages (xunit 2.9.3, Microsoft.NET.Test.Sdk 17.14.1, xunit.runner.visualstudio 3.1.4, coverlet.collector 6.0.4, Microsoft.EntityFrameworkCore.InMemory 10.0.8) are already approved in RESEARCH.md Package Legitimacy Audit and match the versions used in PersonsAPI.Application.Tests / PersonsAPI.Domain.Tests.
