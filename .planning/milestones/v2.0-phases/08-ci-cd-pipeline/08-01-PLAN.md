<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub repo -> GitHub Actions runner | Repository secrets cross into the ephemeral runner VM at job start |
| GitHub Actions runner -> GCP control plane | Runner authenticates with the SA JSON key to push images and deploy Cloud Run |
| Third-party Actions -> runner | `actions/*` and `google-github-actions/*` execute with access to the job environment (including secrets passed via `with:`) |
| Public git history / public logs -> outside world | A public repo exposes workflow logs; secrets must never leak into them |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Information Disclosure | GCP_SA_KEY in run logs | mitigate | Never echo the secret; pass it only via `credentials_json: '${{ secrets.GCP_SA_KEY }}'`. GitHub auto-masks declared secrets. Task 1 acceptance criteria forbids echo + secrets.; Task 2 documents the rule. (RESEARCH Security Domain V7.4.1) |
| T-08-02 | Information Disclosure | GCP_SA_KEY plaintext in YAML | mitigate | Key stored only as a GitHub encrypted secret (AES-256 at rest), referenced by name in YAML — never inlined. `.gitignore` already excludes `key.json` (Phase 7). (Security Domain V6.2.1) |
| T-08-03 | Elevation of Privilege | Overprivileged Service Account | mitigate | SA `persons-api-deployer` holds only `roles/artifactregistry.writer` + `roles/run.admin` (least privilege, set in Phase 7 DEPLOYMENT.md Step 5). No Owner/Editor. Workflow grants no extra perms. (Security Domain V4.1) |
| T-08-04 | Elevation of Privilege | Excess GitHub OIDC token scope | mitigate | Each job sets `permissions: contents: read` and omits `id-token: write` (not needed for SA key auth). Task 1 acceptance criteria forbids the string `id-token`. (RESEARCH Pitfall 2) |
| T-08-SC | Tampering | Third-party GitHub Actions supply chain | mitigate | Pin all actions to major-version tags from verified first-party orgs (GitHub actions/*, Google google-github-actions/*); no `@latest`/`@main`. No npm/pip/cargo installs occur, so no Package Legitimacy checkpoint is required (RESEARCH Package Legitimacy Audit: all four actions Approved, first-party). |
| T-08-05 | Denial of Service / Tampering | Whitespace-corrupted GCP_SA_KEY | accept-with-control | Minified single-line JSON required; documented in Task 2 with the newline-stripping minify command. Failure is loud (JSON parse error) and non-destructive — caught on first `workflow_dispatch` test run. (RESEARCH Pitfall 5) |

**Package Legitimacy:** No npm/pip/cargo installs in this phase. GitHub Actions are resolved by the runner from first-party GitHub/Google orgs; RESEARCH.md Package Legitimacy Audit marks all four (actions/checkout@v4, actions/setup-dotnet@v4, google-github-actions/auth@v2, google-github-actions/setup-gcloud@v2) as Approved. No [ASSUMED]/[SUS]/[SLOP] packages — no blocking-human checkpoint required.
</threat_model>
