<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Docker daemon ← build context | Files sent from the workstation into the build; `.dockerignore` controls what crosses |
| MCR ← image pull | Base images pulled from `mcr.microsoft.com` over TLS |
| Container process ← host | The running container process; isolation depends on the user it runs as |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Elevation of Privilege | Container runtime user | accept | `aspnet:10.0` runs as non-root `app` user by default since .NET 8; no `USER root` override is added, so the default non-root user is preserved |
| T-06-02 | Information Disclosure | Build-time layers | mitigate | No secrets used during build; NuGet restore pulls only public packages; `.dockerignore` excludes `.git/`, `.planning/`, `.claude/` so repo metadata never enters the context |
| T-06-03 | Tampering | apt-get curl install | mitigate | Single minimal package installed with `--no-install-recommends`; apt lists removed (`rm -rf /var/lib/apt/lists/*`) to limit residual attack surface |
| T-06-04 | Information Disclosure | Environment variables in image | accept | Only `ASPNETCORE_HTTP_PORTS=8080` is baked in — non-sensitive port config, no secrets |
| T-06-SC | Tampering | Base image provenance | mitigate | Base images pulled exclusively from official `mcr.microsoft.com/dotnet/*` over TLS; no third-party registries. No npm/pip/cargo installs in this phase, so the package legitimacy gate does not apply |
</threat_model>
