## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Developer machine -> git repository | Service account JSON key (key.json) created locally; must never cross into version control |
| Public internet -> Cloud Run service | Unauthenticated callers reach all 6 API endpoints once deployed (--allow-unauthenticated) |
| Developer machine -> GCP IAM | Service account is granted project-level IAM roles; over-permissioning escalates blast radius |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Information Disclosure | Service account key.json | mitigate | Task 1 adds `key.json` to .gitignore BEFORE Step 5 (key creation) is documented; DEPLOYMENT.md Step 5 includes a never-commit Warning and instructs storing the key securely for Phase 8 |
| T-07-02 | Elevation of Privilege | persons-api-deployer service account IAM | mitigate | Runbook grants only `roles/artifactregistry.writer` + `roles/run.admin` (least privilege per D-09) — never Owner/Editor; documented explicitly in Step 5 |
| T-07-03 | Elevation of Privilege | Public Cloud Run endpoint (--allow-unauthenticated) | accept | Intentional per D-07 for a learning/demo project with seeded non-PII data; required to verify success criteria with plain curl. DEPLOYMENT.md notes the API is fully public including write endpoints |
| T-07-04 | Tampering | Docker image content | accept | Image is built from the project's own validated Phase 6 Dockerfile; no third-party base beyond official mcr.microsoft.com/dotnet images; no npm/pip/cargo installs in this phase |
| T-07-05 | Information Disclosure | GCP project / billing misconfiguration | mitigate | Runbook documents billing linkage as a manual Console step and uses placeholder PROJECT_ID so no real project identifiers are committed to the repo |
| T-07-SC | Tampering | npm/pip/cargo installs | accept | No package-manager installs occur in this phase — infrastructure + documentation only; no legitimacy gate applicable |
</threat_model>
