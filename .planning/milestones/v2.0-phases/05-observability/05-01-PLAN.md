<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → `/health` | Public unauthenticated HTTP requests reach the health endpoint (intentional per D-03 for Cloud Run liveness probe) |
| client → API endpoints | Existing public unauthenticated HTTP surface (carried forward from v1.0; auth deferred to v3 SEC-01) |
| process → stdout | Serilog writes structured JSON to stdout, eventually ingested by Google Cloud Logging |
| npm/nuget supply chain | Two new NuGet packages (`Serilog.AspNetCore`, `Serilog.Formatting.Compact`) introduced into the build |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Information Disclosure | `/health` response body | accept | Body is the literal string `{"status":"Healthy"}` — no PII, no internal version info, no stack traces, no environment data. Default ASP.NET Core JSON response is intentionally minimal. Acceptable per industry convention; D-03 mandates anonymous access. |
| T-05-02 | Information Disclosure | Serilog stdout logs | mitigate | EF Core namespace filtered to Warning (D-09) so query payloads — which could echo `Person` data — never reach Information-level sinks. AspNetCore namespace filtered to Warning (D-10) suppresses verbose request-path logs. CLEF format is structured: future redaction filters can target specific properties without parsing free text. |
| T-05-03 | Denial of Service | `/health` endpoint | accept | Endpoint is anonymous and lightweight (no DB hit, no external call — default AddHealthChecks with zero registered checks just returns Healthy). Cloud Run protects upstream with its own rate limiting; this is the intended Cloud Run liveness probe target. No additional mitigation warranted at this layer. |
| T-05-04 | Tampering | `appsettings.json` simplification | mitigate | Removing the `"Logging"` block has zero runtime effect because Serilog ignores it (D-05); behavior change is observable only via log output format, validated by acceptance criteria. No secret values or config keys are removed. |
| T-05-SC | Tampering | NuGet package supply chain (Serilog.AspNetCore, Serilog.Formatting.Compact) | mitigate | Both packages are first-party from the Serilog organization (https://github.com/serilog), Apache-2.0 licensed, used by millions of .NET projects. `Serilog.AspNetCore` and `Serilog.Formatting.Compact` are the canonical Serilog packages — not typosquats. Pin exact versions in csproj (`9.0.0` and `3.0.0` respectively) so future restores cannot pull a hijacked patch silently. |
| T-05-05 | Repudiation | Application logs | mitigate | Serilog CLEF format includes timestamp (`@t`), level (`@l`), and templated message (`@mt`) by default — every log event carries an immutable timestamp suitable for forensic review once ingested by Cloud Logging. No additional structured fields needed at this phase. |
</threat_model>
